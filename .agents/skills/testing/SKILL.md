name: testing
description: Добавляет и запускает поведенческие проверки Planner по specs; защищает существующие тесты от подгонки под код и различает уровни интеграции.
---

Прочитай релевантные canonical specs и docs/architecture/testing.md. Свяжи проверку с требованием или подтверждённым дефектом; выбирай уровень по наблюдаемому эффекту.

**Запрещено менять существующие тесты только ради зелёного прогона. Изменять существующий тест разрешено лишь при явно изменившемся соответствующем требовании.** Укажи источник, старое/новое требование и смысл правки в change/отчёте. Если тест конфликтует с неизменённой spec, зафиксируй конфликт, не подгоняй тест молча.

Не удаляй assertions, не добавляй skip, не расширяй допустимый результат и не заменяй реальную интеграцию mock ради прохождения. Разделяй дефект кода, окружения и изменённое требование; исправляй код при правильном тесте. Детальная диагностика — [debugging-and-error-recovery](../debugging-and-error-recovery/SKILL.md).

Добавляй тесты наблюдаемого результата, отказа и сохранности состояния. Для регрессии по возможности продемонстрируй падение до исправления. Проверяй отмену, ошибку, повторную отправку и терминальные состояния форм; не заменяй это regex по исходникам.

Используй отдельные временные БД и тестовые данные. Запусти релевантные unit/integration/frontend, обязательные lint/build для frontend и затронутую backend-сборку. В отчёте укажи команды, количества, red/green, пропуски и пределы: jsdom/API mocks, браузер и настоящий HTTP-host — разные уровни.
