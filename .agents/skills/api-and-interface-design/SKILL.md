Начни с docs/specs/application/<область>.md и связанной domain spec. Прочитай controller/request/handler/mapping, используемый middleware Common и вызов из scripts/app/api. Зафиксируй вход, результат, отсутствие объекта, недопустимый переход и сохранность данных при отказе.

Перед реализацией согласуй контракт в canonical через [spec-management](../spec-management/SKILL.md). Сохраняй существующие маршруты, числовые enum и необязательность полей, если запрос их не меняет. Не заимствуй pagination, новый формат ошибок или idempotency как неявные бизнес-требования.

Валидация входа не заменяет локальные доменные invariant; место правил задаёт architecture. Проследи все потребители изменённого поля. Добавь проверку round trip и отказа через [testing](../testing/SKILL.md); для HTTP-изменения проверь фактическую сериализацию/маршрут, не только handler.

Выход — совместимый проверенный контракт либо явно описанное согласованное изменение с миграцией потребителей; проверку middleware не выдавай за проверку только DTO.
