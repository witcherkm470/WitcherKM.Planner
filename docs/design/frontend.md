# Дизайн frontend

## Назначение

Этот документ фиксирует визуальную систему существующего React-интерфейса и правила её развития. Стиль — сдержанное взрослое фэнтези: гримуар, перо, черепа и авторские сигилы. Визуальная метафора не должна ухудшать читаемость или превращать рабочий интерфейс в декоративную иллюстрацию.

Текущая реализация использует тему **«Светлая таблица с тёмной шапкой»**. Если в задаче тема не указана, применять именно её. Темы «Светлая лаванда» и «Тёмный гримуар» остаются равноценными вариантами для явно запрошенной смены темы или сравнения.

## Текущая визуальная основа

- Фон приложения: `#f3f0f8`.
- Поверхности карточек и таблиц: `#faf8ff`.
- Граница: `#d8cde7`.
- Основной текст: `#372b49`; вторичный текст: `#625570`.
- Шапки таблиц и карточек: `linear-gradient(110deg, #25434d 0%, #40345e 46%, #50365f 75%, #59364e 100%)`.
- Разделители: `#e5ddef`; строка при наведении: `#eee7f8`.
- Тень: `0 2px 6px rgba(41, 30, 64, 0.10), 0 8px 24px rgba(92, 65, 140, 0.08)`.

Эти значения уже встречаются в `MainLayout.module.scss`, `ProjectCard.module.scss`, `FeatureTable.module.scss` и компонентах таблиц. При изменении существующего компонента сначала сверять его текущие значения, а не создавать близкие, но разные оттенки без причины.

При смене палитры сохранять структуру, размеры, отступы, шрифт и поведение компонента. Не смешивать значения разных тем в одном компоненте.

## Таблицы и карточки

- Контейнер таблицы: ширина `100%`, `overflow: hidden`, граница `1px`, радиус `12px`.
- Таблица: `width: 100%`, `border-collapse: collapse`, `table-layout: fixed`.
- Градиент задаётся на `thead`; `th` остаётся прозрачным, чтобы градиент был непрерывным.
- Ячейки и заголовки имеют `padding: 14px 16px`; заголовки — `font-weight: 600`, ячейки — `400`.
- По умолчанию содержимое центрировано; содержательные текстовые столбцы выравниваются влево.
- Последняя строка не имеет нижней границы.
- Состояния и счётчики оформляются компактными `pill`-бейджами, а не отдельными яркими блоками.
- Карточка проекта использует ту же поверхность, границу и характер шапки, что и таблицы.

## Кнопки и состояния

- Компактная кнопка действия: flex-центрирование, `34px × 34px`, граница `1px`, радиус `8px`.
- Для крупной кнопки действия в карточке текущий размер `40px × 40px` сохраняется.
- Обычные кнопки: фон `#f1eafa`, граница `#d6c8e7`, текст `#594274`.
- Переходы цвета — `0.15s ease`, перемещения — `0.1s ease`; при hover кнопка может подниматься на `1px`, при active возвращается в исходное положение.
- Hover для редактирования: `background-color: #f8dc52; border-color: #edc745`.
- Hover для удаления: `background-color: #ff5e5e; border-color: #f33e3e`.
- `:focus-visible` обязателен для интерактивных элементов; не заменять его только эффектом hover.
- При `prefers-reduced-motion: reduce` отключать декоративные transition и animation.

## SVG-иконки

- Иконки хранятся отдельно в `scripts/app/assets/` в формате SVG без растровых вложений, внешних зависимостей и шрифтов.
- Для кнопок: `width="24"`, `height="24"`, `viewBox="0 0 24 24"`; основные линии ориентировочно `1.5–2`, вспомогательные — `1.2–1.3` единицы.
- Основной градиент направлен снизу слева вверх направо: `#20C5DB` (0%), `#9A79EF` (46%), `#C66ADE` (72%), `#EC6191` (100%).
- Базовые дополнительные цвета: тёмный `#291E40`, сливовый `#594274`, светлая деталь `#FFF4FF`.
- Для пера редактирования использовать асимметричное опахало и плавный светлый стержень; для удаления — компактный череп с тёмной заливкой, градиентным контуром и светлыми глазницами.
- У каждого SVG должен быть уникальный идентификатор градиента, чтобы иконки не конфликтовали при inline-вставке.
- Небольшие иконки проверять в их реальном размере: не добавлять мелкие детали, превращающиеся в шум.

## Что не использовать

- мультяшный стиль, неоновое свечение, чрезмерный декор и россыпь звёзд;
- месяц со звёздочкой без явной задачи;
- растровые изображения внутри SVG;
- не подтверждённые исторические или алхимические трактовки авторских сигилов.

## Правило выдачи CSS

Если задача требует заменить стили конкретного компонента, предоставлять полный CSS/SCSS этого компонента, пригодный для целостной замены, а не только набор цветовых переопределений. Исключение — когда пользователь явно просит точечную правку.
