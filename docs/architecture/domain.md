# Технические правила Domain

Продуктовые правила находятся в [domain specs](../specs/domain/glossary.md); здесь способ их реализации.

- Сущность защищает локальные инварианты в конструкторе и поведенческих методах. Закрытые setters; application не должен обходить методы через прямую запись состояния.
- Проверку допустимости удаления по собственному статусу размещать в EnsureCanDelete сущности; обработчик вызывает её перед Remove. Наличие связанных записей проверять репозиторием, когда граф не загружен полностью.
- Value Object вводить только при появлении самостоятельного понятия с собственной семантикой значения/равенства и совместными правилами. Не оборачивать каждый string или id ради DDD. Сейчас отдельные VO не требуются.
- DomainException из Common — нарушенный локальный инвариант/недопустимый переход; EntityNotFoundException в application — отсутствующий объект. Не добавлять домену HTTP/EF/MediatR-зависимости.
- Навигация EF может быть незагруженной. Межобъектное правило требует явной загрузки необходимых данных или внешней проверки. Не делать вывод о пустой базе по пустой коллекции объекта.
- EF-конструктор не заменяет публичный валидирующий конструктор; изменение persistent-модели требует новой миграции, старые миграции неизменны.

Существующее направление project references описано в overview.md; перенос интерфейсов репозиториев в другой слой не входит в эту миграцию SDD.
