# Frontend

## Стек и точка входа

Клиент находится в `scripts/` и использует React 19, TypeScript, React Router 7, Axios, Vite и SCSS Modules. Точка монтирования — `app/main.tsx`; маршруты определены в `app/App.tsx`.

Vite в режиме разработки проксирует `/api` на `http://localhost:5062`. `apiClient` использует относительный `baseURL: "/api"`.

## Структура

| Каталог | Ответственность |
| --- | --- |
| `app/api/` | Axios-клиент, endpoint-функции, модели запросов/ответов и типы ошибок. |
| `app/components/` | Переиспользуемые UI-компоненты: layout, таблицы, карточки, модальные окна, tooltips. |
| `app/hooks/` | Повторно используемая логика запросов и действий с фичами. |
| `app/views/` | Страницы, связывающие маршруты, запросы и компоненты. |
| `app/assets/` | SVG-иконки. |
| `app/*.css` | Глобальные стили и начальные стили приложения. |

## Маршруты

| Маршрут | Страница |
| --- | --- |
| `/` | Перенаправление на `/projects`. |
| `/projects` | `ProjectsPage`. |
| `/projects/:projectId` | `ProjectPage`. |
| `/features` | `FeaturesPage`. |

`MainLayout` предоставляет постоянную боковую навигацию и рендерит страницы через `Outlet`.

## Данные и ошибки

Endpoint-функции определены в `api/apis/project/projectApi.ts` и `api/apis/feature/featureApi.ts`. Страницы должны использовать эти функции, а не составлять URL в JSX-компонентах.

`useApiRequest` инкапсулирует данные, загрузку, ошибку, очистку ошибки и `onSuccess`. После успешного изменения текущие страницы перезагружают данные с API. `useFeatureActions` объединяет диалоги и запросы изменения/удаления фич.

Ответы API и ошибка отсутствия сети представлены типами из `api/models/` и `api/errors/`. Ошибки выводятся через `ErrorModal`.

## Правила frontend

1. Не помещать HTTP-вызовы, URL или модели API в визуальные компоненты: размещать их в `app/api/`.
2. Новую страницу добавлять в `views/`, маршрут — в `App.tsx`, а повторно используемый UI — в `components/`.
3. Состояние запроса и повторное получение данных размещать в page или hook, а не в таблице, карточке или модальном окне.
4. Использовать TypeScript-типы моделей API; не дублировать контракт ответа вручную в компоненте.
5. Для scoped-стилей компонента использовать соседний `*.module.scss`; глобальные стили оставлять минимальными.
6. Сохранять доступность: осмысленные `aria-label`, доступная клавиатурная навигация, видимый `:focus-visible`, кнопки с `type`.
7. Соблюдать [дизайн frontend](../design/frontend.md), если задача меняет UI или SVG.
8. Перед сдачей изменений frontend запускать из `scripts/` как минимум `npm run lint` и `npm run build`.

Текущий код не содержит отдельного state manager, библиотеки компонентов, дизайн-токенов или тестовой инфраструктуры. Не добавлять их без отдельного требования и спецификации.

Строгий порядок выполнения frontend-задач находится в [rules/frontend.md](../rules/frontend.md).
