# Спецификации Planner

Canonical specs описывают согласованное действующее поведение. Это не снимок любых случайных особенностей кода: найденный баг исправляется по требованию, а требование не переписывается под баг.

## Изменения

Один документ в changes/active на изменение, затрагивающее любое число слоёв. Не создавать пары actual/changes для каждой области. В change фиксируются источник запроса, изменяемые требования, затронутые canonical-файлы, критерии приёмки, проверки и вопросы.

Сначала согласовать изменение требования, затем реализовать его и проверить. Canonical обновляются в том же изменении только в пределах явно заданного требования. Агент не уполномочен менять смысл требования ради прохождения тестов. После реализации и проверок change переносится в changes/archive вместе с результатами; архив не является вторым источником действующих требований. Незавершённое изменение остаётся active с явным статусом.

При конфликте источников остановить только зависимую часть, записать вопрос и продолжить независимые исправления. Текущая просьба пользователя может уточнять старую spec, но предположение агента — нет.
