# Конфигурация и секреты Planner — 2026-10-22

Источник: согласованная с владельцем схема локальной разработки и будущего размещения Planner на собственном сервере. Приватный EcosystemSettings служит каталогом значимых настроек; действующие ключи поступают в API при запуске.

## Требование и границы

- Обычные настройки остаются в конфигурации приложения. Рабочий `MediatR:LicenseKey` отсутствует в исходниках, NuGet-пакетах и Docker-образах.
- Локальная разработка получает ключ из .NET User Secrets. Docker получает его из файла секрета, подключённого только к API; отсутствие ключа завершает запуск понятной ошибкой без раскрытия значения.
- API использует стандартные источники `IConfiguration`. Новая утилита в Common и библиотека настроек во время запуска не нужны. Приватный EcosystemSettings содержит список ключей, примеры и правила их заполнения без рабочих значений.
- Контейнерный сценарий сохраняет один простой запуск, предварительные проверки и SQLite-том. Образ можно в дальнейшем собрать отдельно и разместить на сервере без доступа к приватному GitHub во время запуска.
- Предметные сценарии Project/Feature/Task/Idea и HTTP-контракты не меняются.

## Приёмка

1. Локальный API запускается с User Secrets и сообщает об отсутствии ключа, если ни один разрешённый источник его не содержит.
2. Docker Compose передаёт ключ API через secret-файл; файл не попадает в Git и контекст сборки, а образ запускается без GitHub-токена и EcosystemSettings.
3. Скрипт первого локального Docker-запуска запрашивает ключ скрыто, сохраняет его только в игнорируемый файл и не требует повторного ввода при обновлении.
4. Зависимости и инструкции Planner согласованы с Common 0.1.5; черновые HTTP-загрузчик и пакет настроек удалены.
5. Существующие backend/frontend проверки остаются действительными; сборка и контейнерный запуск проверены в доступной среде.

## Результат и проверки

- Planner использует стандартные `IConfiguration`/`User Secrets`/`KeyPerFile`, без пакета EcosystemSettings и HTTP-загрузки. Ссылки Common оставлены на 0.1.5; черновой механизм настроек Common удалён, SDD-документация Common сохранена.
- Рабочий файл `appsettings.json` удалён из текущего дерева EcosystemSettings; каталог содержит только имена, назначение и пример без значения. Старые коммиты Git всё ещё содержат прежнее значение: удаление файла не является ротацией ключа или переписыванием истории.
- `dotnet restore`, `dotnet build` API и `dotnet test` прошли; backend 25/25. API в Development с User Secrets ответил HTTP 200, без ключа в Production завершился сообщением `No MediatR license key specified.` без вывода значения.
- Синтаксис PowerShell-скриптов и сохранение JSON через `dotnet user-secrets set` проверены. Docker Compose config для локального и серверного шаблона прошёл.
- Docker API test-stage собрался, backend внутри контейнера 25/25. Готовый API-образ собрался и обновлённый Compose поднял сервисы; web и `/api/projects/get-projects` ответили HTTP 200. Файл секрета обнаружен только в API-контейнере, отсутствует в web-контейнере и в готовом API-образе.
- Frontend локально: 28/28 тестов, lint и production build прошли. Полный `docker.ps1 check` остановился после успешной проверки API из-за временного DNS-сбоя при обращении Docker Hub за `node:24-alpine`; frontend-исходники не менялись, а уже собранный web-контейнер успешно обслужил HTTP-запрос.
- Шаблон будущего сервера проверен как Compose-конфигурация; реального сервера, домена, HTTPS и аутентификации пока нет, поэтому публичное развёртывание не выполнялось.
