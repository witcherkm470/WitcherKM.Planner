# Запуск Planner в Docker

Источник: запрос пользователя от 2026-10-22 на совместный запуск API и фронтенда,
полное развёртывание в Docker и простой порядок обновления с проверкой до пуша.
Уточнение: один PowerShell-файл, запускаемый из папки или терминала, выполняет весь
цикл проверки, обновления и запуска контейнеров.

## Область

- Новых продуктовых сценариев и изменений canonical specs нет: меняется способ сборки,
  запуска и хранения уже существующего приложения.
- Техническая схема описана в `docs/architecture/overview.md`; пользовательские команды —
  в `README.md`.

## Критерии

1. Docker собирает API и фронтенд из локального дерева Planner и соседнего Common.
2. Одна команда запускает оба сервиса; фронтенд обращается к API через один адрес.
3. SQLite переживает пересоздание контейнеров, ключ MediatR не попадает в Git или образы.
4. Запуск `docker.ps1` без параметров проверяет backend-тесты, frontend-тесты, lint
   и обе сборки до обновления контейнеров; `check` доступен отдельно.
5. Обновление локального Docker не выполняет Git pull/push и сохраняет базу.
6. Первый запуск запрашивает ключ MediatR, сохраняет его только в игнорируемом `.env`;
   пример конфигурации не содержит рабочего ключа.

## Результат и проверки

- На хосте прошли 25 backend-тестов, 28 frontend-тестов, frontend lint, frontend build
  и публикация API (Release). Опубликованный API с временной SQLite-базой вернул
  HTTP 200 для `GET /api/projects/get-projects`.
- После установки WSL и запуска Docker Desktop команда `docker.ps1` без параметров
  успешно собрала оба образа, проверила backend (25/25), frontend (28/28), lint и
  запустила API с web. Прямой запуск `docker.ps1 check` по полному пути из другой
  папки тоже завершился успешно.
- `http://127.0.0.1:8080/` вернул HTTP 200 и HTML клиента; `/api/projects/get-projects`
  вернул HTTP 200 и корректный JSON. Docker Compose показывает оба контейнера в
  состоянии running.
- При принудительном пересоздании контейнеров именованный том остался прежним:
  временная метка и файл SQLite сохранились; после проверки метка удалена, API снова
  вернул HTTP 200.
- `.env` исключён из Git и Docker-контекста; `.env.example` содержит только заглушку.
  PowerShell-парсер и `git diff --check` прошли.
- При самой первой холодной сборке frontend один тест упал; повторная сборка и ещё
  десять запусков набора в контейнере прошли (28/28). Причина единичного сбоя не
  воспроизведена, тесты и ожидания не менялись.
