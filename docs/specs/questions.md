# Открытые вопросы

Эти вопросы не разрешены изменением бизнес-логики.

- Q-01. В legacy/features/feature-card.md написано «Кнопки редактирования проекта» на карточке фичи. Нужен ли отдельный запуск редактора родительского проекта именно здесь? Существующее редактирование самой фичи сохранено. Дополнительное действие над проектом не добавлено.
- Q-02. Нужен ли пользовательский сценарий закрытия/открытия проекта? Домен уже умеет закрывать при завершении всех фич; в API/UI такого сценария нет и старые specs его не требуют. Он не добавлен.
- Q-03. Что делать при удалении фичи с задачами: запрещать явно в application, переносить задачи или каскадно удалять? Существующий FK Restrict сохранён; данные не удаляются каскадом.
- Q-04. Должны ли статус фичи и её задачи влиять друг на друга (например, запрет завершения с открытыми задачами или запрет новых задач у Completed)? Таких требований нет; новые ограничения и автоматические переходы не введены.

Определённые без новых бизнес-правил уточнения: Done в старых текстах о фиче соответствует Completed в API; Open у задач остаётся Open. Выбор фичи в общей форме создания задачи необходим из T-01 и существующего API; в карточке фичи родитель фиксируется контекстом. Редактирование карточки проекта остаётся существующим inline-редактором с диалогом несохранённых изменений.
