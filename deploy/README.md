# Запуск готовых образов на своём сервере

Это шаблон для будущего размещения Planner на сервере с Docker Compose. API и web-образы собираются и проверяются заранее, затем публикуются в выбранный реестр. Серверу нужны доступ к этим образам и файлы конфигурации из этой папки; репозитории Common и EcosystemSettings ему не нужны.

1. Скопируйте `images.env.example` в `images.env` и укажите версии двух опубликованных образов. Используйте фиксированные теги или digest, чтобы обновление было предсказуемым.
2. Создайте на сервере `secrets/MediatR__LicenseKey` с рабочим ключом MediatR. Файл не входит в Git или образ. Ограничьте права на хосте, но оставьте чтение для пользователя API-контейнера (`uid=1654`, `gid=1654` в текущем образе); например, владелец файла — пользователь развёртывания, группа — 1654, режим — `0640`. Docker Compose монтирует файл с его фактическими правами. Включите файл в защищённое резервное копирование.
3. В этой папке выполните `docker compose --env-file images.env pull`, затем `docker compose --env-file images.env up -d`. При обновлении измените версии образов и повторите эти команды. Именованный том `planner-data` сохраняет SQLite.

Web опубликован только на `127.0.0.1:8080`. Перед доступом клиентов из интернета нужны домен, HTTPS через reverse proxy и защита пользовательского доступа; этого в шаблоне пока нет. Не открывайте порт напрямую в интернет. Значения секретов остаются на сервере и не передаются браузеру или мобильному клиенту.

Docker Compose монтирует файл секрета в API как `/run/secrets/MediatR__LicenseKey`; стандартный .NET provider отображает его в `MediatR:LicenseKey`. При отсутствии или пустом значении API не запускается.
